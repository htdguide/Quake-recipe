# QW/server/progdefs.h

> Data, generated: the layout of the globals and entity fields the engine and the compiled game logic must agree on, for QuakeWorld's larger field set.

**Needs** — nothing
**Used by** — [`progs.h`](progs.h.md) · [`pr_edict.c`](pr_edict.c.md) · [`pr_cmds.c`](pr_cmds.c.md) · every `sv_*.c`
**Tier floor** — T1: it is a record layout shared with a separately compiled program

## Purpose

The binary contract between the engine and the game logic, generated by the game-logic compiler from the shared declarations
([`defs.qc`](../../qw-qc/defs.qc.md)) and then compiled into the engine. Where the original's version is two dozen lines, this one
is a hundred and sixty, and the difference is what a networked game needs to say.

## State

As [`progdefs.h`](../../WinQuake/progdefs.h.md); the records are unchanged except where **What differs** says otherwise.

## What it records

**The globals the engine reads and writes**, in a fixed order after a reserved run of slots:

```text
self, other, world            -- the entity references the engine sets before a call
time, frametime               -- the clock the game logic sees
newmis                        -- a projectile created this frame (sv_phys.c)
force_retouch                 -- make every trigger re-fire next frame
mapname, serverflags
total_secrets, total_monsters, found_secrets, killed_monsters
parm1 .. parm16               -- the persistent per-player parameters
v_forward, v_up, v_right      -- the basis the engine computes on request
trace_allsolid, trace_startsolid, trace_fraction, trace_endpos,
trace_plane_normal, trace_plane_dist, trace_ent, trace_inopen, trace_inwater
msg_entity                    -- the destination of a directed message
the named functions the engine calls into: main, StartFrame,
  PlayerPreThink, PlayerPostThink, ClientKill, ClientConnect,
  PutClientInServer, ClientDisconnect, SetNewParms, SetChangeParms
```

**Invariants** —

- **The order is the contract.** Every entry is addressed by its slot offset, computed at load from the compiled program's own
  definition table and checked against a checksum ([`pr_edict.c`](pr_edict.c.md)). Reordering anything breaks every compiled
  program.
- **The trace results are globals, not a returned value**, because the language has no records. So a trace operation writes nine
  globals and the game logic reads them immediately — meaning **a trace's results are invalidated by the next trace**, and
  interleaving two traces is a real bug a modification can write. A rebuild designing a game interface should return a value.
- **The projectile-created global is the signal for the immediate projectile pass**
  ([`sv_phys.c`](sv_phys.c.md)), and is the only global the engine reads *after* a call rather than before.
- **The sixteen persistent parameters are the whole of per-player persistence**, carried across level changes
  ([`sv_init.c`](sv_init.c.md)). Sixteen numbers, and a modification that needs more must encode.
- **The named functions are the engine's callbacks into the game logic**, and the list is the whole of the game's lifecycle:
  start of frame, before and after a player's movement, connect, spawn, disconnect, and the two parameter handlers. That list is
  worth reading as the specification of when a game rule can run.
- QuakeWorld adds the spectator callbacks and the projectile signal to the original's set; a program declaring the original's set
  fails the checksum, which is why the two engines' game logic is not interchangeable.

**Notes** — the file is generated, so it is **data and not a decision** — except that its content *is* the interface, and it is
generated from [`defs.qc`](../../qw-qc/defs.qc.md), which is a decision. A rebuild that keeps the language regenerates this; one
that does not should read it as the list of what the engine and the game must share.
